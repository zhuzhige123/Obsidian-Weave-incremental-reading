# 设计理念

本章说明 Weave Incremental Reading **为什么**这样设计，以及它**不是**什么。读完后，你对「该用添加还是导入」「该不该指望 FSRS」会有清晰边界。

## 收藏不等于读过

稍后读、书签、剪藏文件夹解决的是「先存下来」。它们通常不回答：

- 今天该读哪几条？
- 昨天逾期的怎么办？
- 同一本书拆成多段后，怎样顺着读下去？
- 打开时能否回到当初那个位置？

本插件把材料收成**阅读点**，用**日历**做每日节奏，用**溯源链接**保证续读——目标是让队列真正动起来，而不是躺在收藏夹里。

## 三个设计原则

### 1. 决策在日历，内容在原文

日历负责：选日、看负载、排优先级、标记进度、改期与搁置。  
原文负责：真正阅读。打开阅读点即按类型回跳 Markdown / PDF++ / Canvas / 网页 / EPUB。

不要期待在插件里再嵌一套「第二阅读器」当日常主路径；主路径是**队列 + 回跳**。

### 2. 一条主路径，多种入口

日常新增的推荐路径始终是日历顶部的 **「添加链接」**（命令侧常写作「添加阅读目标」）：一条链接、一个选区、一个节点。

**导入阅读材料**留给「整份文档 / 整本书目录 → 大量阅读点」。  
**订阅文件夹**留给「剪藏收件箱持续自动补齐」（高级功能）。

入口可以多，概念不要散：最终都落成专题里的阅读点，并出现在日历上。

### 3. 增量阅读 ≠ 间隔复习（FSRS）

| | Weave Incremental Reading | Weave 主插件（Deck） |
|--|---------------------------|----------------------|
| 解决什么 | 读什么、何时再出现、如何续读 | 记住什么、间隔多久复习 |
| 核心单位 | 阅读点 + 专题 + 日历 | 记忆卡片 + 牌组 |
| 典型算法感 | 统一默认节奏、时间预算、日上限、负载顺延 | FSRS 等间隔复习 |

把「读队列」和「记卡片」拆开，是有意为之：你可以只装本插件做阅读节奏；需要制卡与复习时再装主插件。教程与设置里出现的调度，指的都是**阅读点日程**，不是 FSRS。

## 为什么用专题（`.irdeck`）

专题把阅读点按主题或计划分组，并以库内文件保存：

- 可备份、可同步、可在文件管理器中看到
- 打开 `.irdeck` 可在专题视图与日历之间切换
- 月历标题旁的专题 chip 可过滤「全部」或某一专题

命名保持稳定，避免同一计划被拆成多个拼写不同的专题（否则日历与过滤会「看起来像重复项目」）。

## 为什么强调续读位置

增量阅读的价值很大一部分在「打断后还能接上」。因此每种来源都尽量保存稳定定位：

- Markdown：块 / 行锚点
- PDF：页码与选区（精确选区建议配合 PDF++）
- Canvas：节点 ID
- 网页：URL（通常配合摘录笔记载体）
- EPUB：章节 / CFI（需 Weave EPUB Reader）

创建时多花一步确认位置，之后从日历打开才「一下回到原文」。

## 免费基线与高级扩展

产品默认保证：**日历 + Markdown 阅读点 + 添加链接 + 基础调度 + 连续阅读** 即可完成闭环。  
PDF/EPUB 批量章节、订阅文件夹、深度调度策略、计时器、统计、关联笔记等属于高级扩展——需要时再激活，不挡主流程。

## 明确不推荐当作日常方案的内容

| 项目 | 说明 |
|------|------|
